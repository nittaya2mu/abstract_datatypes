## 3. รูปแบบที่ใช้ส่งให้อาจารย์

หากอาจารย์ให้ไฟล์ `timing_template.c` เป็นแม่แบบและให้คัดเฉพาะฟังก์ชัน `MySearch()` ไม่ต้องนำไฟล์นี้ไปแทนทั้งไฟล์โดยอัตโนมัติ เพราะ `MySearch()` ของกลุ่มมีรูปแบบ `MySearch(AVLNode *root, int target)` ซึ่งต้องทำงานกับ AVL tree โดยตรง

สำหรับการตรวจของกลุ่มนี้ ให้ส่ง/รัน **ไฟล์ทั้งไฟล์ `timing_avl.c`** ของกลุ่มด้วยคำสั่งด้านล่าง เพื่อให้โครงสร้าง `AVLNode`, การสร้าง AVL และ `MySearch()` อยู่ในชุดเดียวกัน

## 4. สิ่งที่โปรแกรมรับรอง

- `REPEAT = 1000` ใช้ค่าเดียวกันทุกขนาด
- ตรวจผลค้นหาทั้ง 10 targets ก่อนจับเวลา
- ชุดข้อมูลกลางควรได้ **พบ 7 / 10 และไม่พบ 3** ทุกขนาด
- วัดเวลา 5 ครั้งต่อขนาดข้อมูล
- ตัดค่าต่ำสุดและสูงสุด แล้วเฉลี่ย 3 ค่าที่เหลือ
- จับเวลาเฉพาะ `MySearch()` ไม่รวมการอ่านไฟล์ การสร้าง AVL และการแสดงผล
- ใช้ `data_*.txt` ที่ยังไม่เรียง แล้วสร้าง AVL ก่อนเริ่มจับเวลา ซึ่งสอดคล้องกับกติกาที่อนุญาตให้ BST/AVL อ่านข้อมูลที่ยังไม่เรียงและไม่รวมเวลาเตรียมโครงสร้างในการวัด

## 5. สำคัญในวันนำเสนอ

ผู้สอนกำหนดให้ทุกกลุ่มใช้ **เครื่องกลางเครื่องเดียวกัน** และใช้ชุดข้อมูลกลางเดียวกันเพื่อเปรียบเทียบอย่างเป็นธรรม ดังนั้นตัวเลขเวลาที่เก็บไว้ใน ZIP นี้เป็นเพียงผลตรวจสอบความถูกต้องของโปรแกรม ไม่ใช่ตัวเลขที่จะอ้างแทนผลบนเครื่องกลาง

ให้จดเวลาทั้ง 5 ครั้งของ n = 1,000 / 10,000 / 100,000 ลงตารางของรายงาน แล้วตัดค่าสูงสุดและต่ำสุดออกก่อนคำนวณค่าเฉลี่ย 3 ค่า

## 6. การวิเคราะห์ Big-O

AVL Search มีเวลา `O(log n)` ต่อการค้นหาในกรณีที่ต้นไม้สมดุลตามคุณสมบัติ AVL

หลังได้ค่าเฉลี่ยจากเครื่องกลาง ให้คำนวณเลขชี้กำลังเชิงประจักษ์ระหว่างสองขนาดด้วย

`k = log(เวลาใหม่ / เวลาเดิม) / log(ขนาดข้อมูลใหม่ / ขนาดข้อมูลเดิม)`

แล้วอธิบายแนวโน้มเทียบกับ `O(log n)` โดยไม่คาดหวังว่าค่าที่วัดจริงจะตรงทฤษฎีแบบเป๊ะ เนื่องจากมีผลจาก clock resolution, cache, compiler และภาระงานของเครื่องกลาง
